# 我们的小厨房 · 情侣电子菜单

一个单文件网页（`index.html`，34 KB，零依赖、零后端），点菜的人点，掌勺的人看单。
手机上用微信打开就能用，数据存在自己设备的 localStorage 里。

## 怎么在微信里用

**方式一：直接发文件（最快，不用部署）**

1. 电脑微信把 `index.html` 发到「文件传输助手」；
2. 手机微信里点开这个文件 → 右上角「用其他应用打开」→ 选浏览器；
3. 安卓可直接用微信内置浏览器打开；iPhone 建议用 Safari 打开后「添加到主屏幕」，就像个 App。

> 微信内置浏览器对 `file://` 与本地存储偶有限制，长期用建议方式二。

**方式二：托管成链接（推荐，两个人都能打开）**

任选一个免费的静态托管，把 `index.html` 传上去即可拿到链接：

| 平台 | 做法 | 备注 |
|---|---|---|
| GitHub Pages | 新建仓库 → 上传 index.html → Settings → Pages → 选 main 分支 | 免费、有 `github.io` 域名 |
| Vercel / Netlify | 拖拽文件夹到网页上，几秒出链接 | 免费、支持自定义域名 |
| 腾讯云 / 阿里云 静态网站托管 | 上传到 COS/OSS，开启静态网站 | 国内访问快，需实名 |
| 微信云开发静态托管 | 云开发控制台 → 静态网站托管 → 上传 | 和下一步的小程序同域，最省事 |

拿到链接后直接发微信给对方，点开即用。

> 注意：网页版数据存在「打开它的那台设备」里，两个人的手机各自独立。
> 想要**两个人真正共享同一份订单**（他在自己手机上看到你点的菜），需要接后端——用微信云开发最快，
> 我可以在此基础上加云函数，把订单表换成云数据库，10 分钟能改完。

**方式三：做成真正的小程序（要 AppID）**

网页版不能直接变成小程序。要做小程序需要：注册小程序账号（个人主体可注册，餐饮类目需企业）、
微信开发者工具、把我的页面拆成 `pages/menu` 等 WXML/WXSS/JS 结构。这套我可以直接生成，导入就能编译。

## 功能

- **点菜 / 掌勺**两种角色，右上角一键切换（同一个页面，两种视角）
- **10 个分类、200 道默认菜**（前菜 19 / 早餐 16 / 拿手菜 45 / 锅物 14 / 汤 15 / 主食 23 / 小吃 19 / 甜品 14 / 饮品 16 / 夜宵 19），每道带一句小情话
- **每道菜都有做法**：用时、难度、食材、3–5 步步骤、小贴士
- **掌勺看单就能看教程**：订单里的菜点一下弹出做法，步骤可逐条打勾、进度条实时走，一键复制做法
- **菜谱页**（底部第二个 tab）：200 道菜的制作过程汇总，可按分类筛、按菜名/食材搜（搜「鸡」「土豆」都行），两个人不用谁点单也能翻着看
- 点单车：加减数量、实时合计、底部悬浮条
- 下单：写备注（"今天想被偏爱一点"）、填开饭时间 → 生成订单卡片
- 下单后**自动复制一段微信文案**，直接粘给对方
- 掌勺视角：接单开火 → 做好了，状态实时变
- 设置：改两个人称呼与头像 emoji、增删改菜品（含填做法）、导出备份、恢复默认、清空
- 数据全本地（localStorage），不联网、不上传
- 移动端优先：安全区适配、圆角卡片、点单飘爱心动效

## 做法数据从哪来

以公开菜谱为准，按家常做法收敛成 3–5 步（不追求饭店出品），主要参考：

- [蚂蚁上树 · 美食天下](https://home.meishichina.com/recipe-640803.html)——粉丝泡软剪段、肉末先拍淀粉、"酱料有盐不用另放盐"

> 注：`m.meishichina.com` 移动版这会儿整站 520（Cloudflare 回源错误），改抓 `home.meishichina.com` 桌面版；个别菜谱页也会偶发 520，重试即可。

其余菜品按同一套结构写：先给判断标准（"筷子能插入""表皮起皱""汤汁挂得住"），再给火候和量。


## 两台手机同步订单（新）

默认情况下每台手机数据各自独立。开一个「房间码」，两台手机就能看到同一份订单：

1. A 手机：设置 → 两台手机同步 → 点 **生成房间码**（例如 `K3F9QZ`）
2. A 手机：点 **复制邀请链接**，把链接发微信给 B
3. B 手机：点链接 → 自动加入同一个房间（也可以手动在设置里填房间码）
4. 之后 A 下单 → B 5 秒内看到；B 接单/完成 → A 也同步

实现方式：走 [ntfy.sh](https://ntfy.sh) 的公共消息通道（免费、无需注册、支持 CORS），
房间码就是频道名，订单快照以 JSON 推上去，双方各自合并。**没有任何后端服务器，也不需要填任何 Key。**

- 同步的是：订单（含状态、备注、菜名）、两个人的称呼和头像
- 不同步：菜单本身（各自本地维护）、购物车
- 合并规则：同一条订单按 `upd` 时间戳取新的；删除用墓碑标记，不会互相打架
- 隐私：订单内容发到公共频道，频道名是随机房间码；不要把房间码发到公开群

如果哪天 ntfy.sh 不通，页面顶部会显示「同步失败：…」，此时退回「复制文案」发微信即可，本地照常能用。

## 改菜单

设置页 →「菜单管理」→ 加一道菜 / 点 ✎ 编辑 / ✕ 删除。编辑弹层里除了菜名价格，还有一段「做法」：
用时、难度、食材（用 、分隔）、步骤（**一行一步**）、小贴士。填了步骤，掌勺才看得到教程入口；
留空就只是个普通菜品，不会弹空教程。

想批量改默认菜单：编辑 `index.html` 里的 `DISHES_RAW` 数组（`id/cat/emoji/name/desc/price/tag/r`），
`r.ing` 用顿号分隔、`r.steps` 用分号分隔，运行时会拆成数组。改完把 `MENU_VERSION` 加 1。
老用户下次打开会自动补齐新增的菜、并给没有做法的老菜补上做法，**自己加的菜和删掉的菜都不会被覆盖**
（删除记录存在 `removedIds`，避免删掉的默认菜被"合并"回来）。

## 菜谱数据怎么维护

`index.html` 是成品单文件，但菜谱数据先说清楚来源：200 道菜的原始数据按分类放在 `data-new/*.tsv`，
每行 12 个字段 `id|cat|emoji|name|desc|price|tag|t|lv|ing|steps|tip`，用 `|` 分隔，
食材用顿号、步骤用分号。改完跑：

```bash
python data-new/merge.py --check-only   # 只校验：行数/字段数/id 连续/重名/价格区间/步骤数
python data-new/merge.py                # 校验通过才写进 index.html，并把 MENU_VERSION +1
```

校验会拦住：字段数不对、id 跳号、菜名重复、价格超出 6–68、步骤少于 3 步、desc/tip 里混进分隔符等问题。
不想用脚本也行，直接在设置页改。
